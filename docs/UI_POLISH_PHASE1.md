## 关于“测试资料检索”

只有点击“展开检索工具”后才出现测试面板。此功能用于手动检查材料索引，不影响正常的答辩自动检索。检索请求仍是原来的 `materialApi.search()`，上传限制、资料选择上限、向量距离数值、账号权限均未修改。

## 特意保留的代码与后续清理边界

有些 `stage9`、`stage8b`、`stage7b` 等标识存在于 CSS 选择器、HTML id、localStorage key 或后端历史模块中，是当前系统跨组件通信或兼容的一部分。本次只清除面向用户的阶段文字和部分无用的源码头注释，**不批量替换这些内部标识**。运行状态与接口自检保留，作为真实故障排查功能。

密码修改接口原有认证方式本次没有改变；本次仅去掉“本地测试模式”等引导语。若要加强认证安全，需要单独做安全评审并补充后端测试。

尚未开展的大模型相关项为第 3、17、19、20 项；第二个重复的“17”以用户后续指示为准。其余第 1、4–6、9、11–13、15、16、18 项均不在本轮修改范围。

## 测试与验收

在项目根目录通过 PowerShell：

```powershell
Set-Location 'C:\Users\Kirino\Desktop\interview_system\frontend'
npm.cmd ci
npm.cmd run test:ui
npm.cmd run build
```

以上 `test:ui` 基于 Node.js 内置测试，检查每条文案变更、RAG 折叠状态与交互标记、既有检索调用/上传入口，以及路由和账号逻辑保留。`build` 同时验证 TypeScript 与 Vite 构建。测试不能替代浏览器的实际点击验收。

建议人工登录系统，检查“数据概览”“简历管理”“我的材料”“开始答辩”“答辩会话”的文字显示；打开和收起检索工具，使用两份现有资料执行一次检索。确认旧有注册、上传和答辩仍可使用。

**发布说明（兼容安装器 v2）**：多数文件仍按源码 SHA-256 严格验证；若目标文件发生其他本地修改，会列出冲突路径并在修改任何文件前停止。`frontend/src/main.tsx` 是唯一特殊处理：原补丁只删除四行开发阶段头注释，因此遇到本地改动时采用精确的“只移除这四行已知注释”方式，其他代码、换行符和 UTF-8 BOM 原样保留；如果四行注释已不存在则保留本地文件。安装前备份，失败尝试回滚；不访问或删除 `storage/`、`.env`、个人上传文件。
