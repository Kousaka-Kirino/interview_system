# 第五组：答题交互重构（Stage 18）

> 2026-10-27 · 《系统优化方案》第 15、16 项 · 在 Stage 17 第四组基础上实施

## 工作范围

这次处理“语音草稿和文字输入框重复”“已答题全展开”“难度感受交互繁琐”以及“提前结束提示不清楚”。**不涉及**第 3、17、19、20 项的大模型相关计划、数据库迁移、后端 API 变更，也不新增大模型调用。

1. **统一草稿与提交**：答题会话内只保留 `InterviewSessionPage.tsx` 的 `current-answer` 输入框，手动文字和 Whisper 识别的文字都写到同一个 React 状态。语音组件继续负责录音、转写和倒计时，不再显示自己的 `stage9-draft` 编辑器和普通“提交本题回答”按钮。正常回答仍由 `answerInterview(...)` 传递 `user_feedback`，避免普通语音回答绕过难度反馈。
2. **事件桥接**：`src/lib/answerDraftBridge.ts` 提供轻量页面内事件；转写事件携带当前 `sessionId` 与 `turnId`，页面校验两者后才追加文本。新题开始时停止旧录音和旧转写，旧回调不会追加到新题。已存在的草稿不会被识别内容覆盖。文本最多保留前 10000 字符。
3. **语音/计时状态同步**：录音/转写/跳题进行中暂不允许普通提交；本题或整场倒计时到期且尚未选择“继续”时，普通提交按钮也不可用。原有“继续本题 / 跳过并下一题”“继续本场 / 结束本场”超时提示及计时键保留。
4. **历史题折叠**：已提交问题以原生 `details/summary` 折叠显示，默认只显示题次及评分；用户点击后可查看原题、答案和 AI 建议。当前题在唯一回答框上方突出显示，无须上下滚动寻找题目。
5. **快速反馈**：原来的难度感受下拉框替换为 `😱 太难 / 😐 刚好 / 😎 太简单` 按钮，点选或再次点击取消。后端仍使用 `too_hard/just_right/too_easy/none`，在**提交回答时**附带反馈，保持当前自适应评分契约。
6. **提前结束确认**：原有独立按钮保留；有未答题时会提示题次及“未计入已回答分数，但保留未答数量”的事实。用户取消后不会结束。

## 兼容性说明

- 当前后端针对“超时跳过本题”的特殊流程，是把 `【本题超时跳过：用户选择进入下一题，未实际作答】` 当成文字提交；它**可能被旧模型评分**。本组保留这一行为，不伪称它不会产生 AI 调用。以后若要正式区分跳题和有效答案，需单独设计后端跳题 API/评分排除策略。
- 页面草稿仅存在于当前页面内存中：刷新、离开或重新登录可能失去未提交文字。**此次未新增永久草稿存储**。
- 录音需浏览器授权麦克风、`faster-whisper` 和模型已安装；本次没有更改 Whisper 资源下载方式。浏览器网络中断时依旧先刷新会话检查，避免重复提交。
- 语音和计时仍由独立挂载的组件处理，事件同步只在同一浏览器标签页有效；这不是跨标签/跨设备协作机制。
- 本次只修改前端源代码、测试和文档；不修改 `.env`、`storage`、SQLite 和任何上传资料。

浏览器验收建议：

1. 启动 FastAPI、Vite 和可用 AI 服务，登录并进入一个有效的答辩会话；确认**只有一处**可以输入答案，且问题在输入框上方。
2. 键盘输入部分文字，再录音并转写，确认新文字追加而不是覆盖原文，完成转写后在同一框修改并提交；评分、下一题和追问正常。
3. 点击三种难度反馈，检查被选中状态；再次点击取消。提交后难度反馈恢复未选择，历史题显示为折叠摘要。
4. 连续答两题，确认已答题目默认折叠，点击可展开原文、答案及 AI 建议。
5. 有当前未答题时点击“提前结束”，先选择取消应保持会话；再次确认后进入复盘，未答题数应正确。
6. 配置短计时后等待超时，检查弹窗阻止普通提交，选择“继续”后可以提交；“跳过”仍沿用旧特殊逻辑。
7. 在录音/转写中改变页面或题目，确认旧转写不会写到新题。换账号时不应混入旧账号草稿。
