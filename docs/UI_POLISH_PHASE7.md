# 第七组：复盘后的再练入口（第 18 项非 AI 部分）

> 2026-10-28 · Stage 20（内部版本序号，不是优化清单的第 20 项）· 基于 Stage 19 第六组完整源码

## 目标与范围

- 根据《系统优化方案》第 18 项，补上复盘结束后的下一步入口。
- 本组**只实现不需要新增模型能力的半闭环**：从一场**已结束**的答辩复盘跳到预填的配置页，再由用户确认并创建一场新的常规答辩。
- 第 3、17、19、20 项以及第 18 项中“自动识别薄弱点、针对性推荐和生成题目”的智能部分继续暂缓。按钮准确命名为「沿用本场资料再练一次」，不虚称已准备专属薄弱点题目。
- 不增加新 AI 请求、不改已有模型提示词、不改数据库结构、不迁移旧数据；首次点击入口**不会创建会话或消耗模型费用**。只有用户点击配置页的「开始答辩」后，才调用既有创建答辩接口及原有模型生成第一题。

## 交互流程

1. 打开已完成答辩的 `#report/<会话ID>`。在逐题回答前可见「继续练习，巩固答辩表达」以及「沿用本场资料再练一次」。
2. 点击后转到 `#configure/retry/<会话ID>`；路由仍是现有「开始答辩」页面，不新增导航项。
3. 页面使用原有 `GET /api/interviews/<会话ID>`、简历列表及材料列表三个只读请求加载来源。请求由 Stage 13 登录与账号归属机制保护，不能跨账号读取。
4. 若来源是已完成会话且**原简历仍存在**：预选原简历、仍存在的最多十份原材料，带入原来的评委、初始难度、自适应级别、主问题数、追问次数。
5. 缺失材料明确提示数量，**不替换为其他材料**。如原简历已删除、会话尚未结束、无权访问、接口不可用或原配置非法，显示错误并阻止自动创建；可点「取消沿用，改为普通配置」。
6. 若在**当前浏览器**有原会话有效的每题及整场分钟数，恢复这两个数；否则保留当前账号最近一次的时间设置并提醒核对。**绝不复制原会话截止时间和计时状态**。
7. 用户检查或修改后点击「开始答辩」，调用既有 `POST /api/interviews` 创建**全新**会话，绑定新会话自己的计时键，并正常转到 `#session/<新会话ID>`。原场次及其回答、评分、报告不改动。

## 安全与兼容性

- 使用已有 `GET /api/interviews/{id}` 后端资源归属检查，不能按 URL 随意读取其他用户答辩；不引入公开资料接口。
- 材料必须出现在当前账户的材料列表中才会选中；原简历不存在则**明确失败**，不悄悄改用列表第一份简历。
- 原会话 ID 只用于查找、查询原本存在的本地计时值；计时绑定只写入**新会话 ID**。原有答辩的截止时间、回答、评分、复盘不被写入。
- 本地存储不可用时仍可使用当前页面，但旧场次计时不能完整恢复，会显示提醒。时间与配置都可由用户检查修改。
- 安装器会在修改前验证第六组成果存在；SHA-256 校验补丁及 baseline，尝试仅对无冲突的本地文本修改执行**离线**三方合并，无法安全合并时停止；安装时备份到 `_patch_backups/group7_repeat_时间戳`，写入失败时尝试回滚。
- 不使用网络 Git 命令、不删除 `.env` 或 `storage/`，不修改账号和数据库。
